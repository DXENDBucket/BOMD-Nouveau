# BOMD & Nouveau

把 Bosses of Mass Destruction 的攻击能力编排为 Ars Nouveau 魔符。
当前是 **0.1.0-dev.10**，支持 **Minecraft 1.21.1 / NeoForge** 和 **Minecraft 1.20.1 / Forge**。
Mod ID：`bomd_nouveau`。作者 EndXiom，许可 **LGPL v3**。

需要 Ars Nouveau、Ars Conflux 0.1.18，以及对应版本的 BOMD 和它们自己的前置。
NeoForge 使用 Ars 5.13.1 / BOMD 1.3.3；Forge 使用 Ars 4.12.7 / BOMD 1.1.2。
Iron、Goety、Not Enough Glyphs、Hex Linker 均不是必需依赖。
公共施法、资源和冷却源码保存在 `common/`；加载器入口、网络和效果注册差异放在各自平台层。
Forge 的小型 API 适配从现有模板生成，避免维护两份冷却策略。

全部为 Tier 1；不额外接入统一吟唱，巨拳激光保留自身的蓄力阶段。强化的载荷附加费每次为 10 Mana，
原版 Ars 形态、增强及后续效果的费用另算。创造模式免载荷费用。
巨拳激光有原生 25 tick（1.25 秒）蓄力，然后进入 60 tick 的持续阶段，瞄准使用原生 8 tick 历史。
默认每次有效受伤为 18，增强遵循伤害魔符配置；保留原版受伤无敌时间，不是每 tick 都扣 18 生命。
持续阶段每秒预付 120 Mana，最多三次；蓄力不扣费，但开始时需要足够支付第一秒。增强附加费也按持续秒计算。
自身／友军从眼部沿当前朝向发射；位置触发保留位置和入射方向。激光不会伤害发射者、施法者或其盟友。
光束原生贴图、绘制函数、蓄力声和红色粒子均来自 BOMD；不生成隐藏 Boss，不改变其原生攻击。
激光默认不破坏方块；后续 Ars 效果仍按原有触发位置执行，不会自动附着到每次激光伤害上。

示例：`弹射物 → 巫妖飞弹 → 增强 → 伤害`，或 `触摸 → 孢子喷发`。
替换载荷不会吞掉后续效果。同一形态段只能选择一种弹射物替换，这是 Conflux 的共用规则。
环绕等反复命中的载体按实际触发逐次付费，空蓝会停止当前载荷及其后续编排。

飞弹、花瓣刃及孢子伤害读取对应 Boss 的配置基础值 ×1.5，以困难模式对玩家
造成的护甲结算前伤害为固定基准，不读取施法者的近战属性。
每级增强增加 `EffectHarm.INSTANCE.AMP_VALUE`，原版默认是 2；修改 Ars「伤害」配置后一起改变。
彗星增强每级增加 0.5 爆炸威力，爆炸伤害仍由 Minecraft 计算。
默认关闭彗星破坏地形，可配置开启。

三个黑曜攻击魔符每次有效命中的基础伤害读取黑曜石柱的攻击配置 ×1.5，默认 24；增强按 Ars 伤害魔符的数值提升。
一次收费包含完整攻击序列，不会对冲击波的每个区间或突刺的每一轮再次收费。
实体目标的突刺采用速度预判，不依赖 Boss 专用的玩家历史位置记录，因此其他生物也可以被追踪。
地潜复用原生墙体搜索规则：附近约 3 格内找到墙，再向前寻找最多约 20 格的出口。
地潜属于增益行为，只作用于自身或原版盟友判定认可的生物（如同队生物）；未结盟的中立生物也不会被移动，拒绝目标不扣蓝。
不可破坏方块、未加载区域、世界边界或不足以容纳目标的落点会阻止传送；地潜不支持伤害增强。

在 Ars 抄写台消耗 **古老灵魂 / 虚空荆棘 ×1 + 魔源宝石 ×1 + 27 XP** 制作。
巫妖系列使用 `ancient_anima`，虚空之花系列使用 `void_thorn`。
三个黑曜攻击魔符使用 `obsidian_heart`，地潜使用 `earthdive_spear`；同样需要魔源宝石及 27 XP。
巨拳激光使用 `blazing_eye`、魔源宝石及 27 XP。
使用原生魔符学习方式、原生配方及 JEI 页面；图标引用对应 BOMD 材料。

## 配置

`bomd_nouveau-server.toml` 控制十一种魔符的载荷价格、增强附加费及彗星地形破坏。
它属于服务端配置；通常位于世界的 `serverconfig/`，测试环境也可能将其放在 `config/`。
不添加独立魔力池；使用 Conflux 的 Ars 账户和触发支付。

dev.8 的费用复核包含 Iron 法术的等级成长及既有 BOMD 冷却；详见审计文档。
升级不会覆盖旧配置的自定义数值。要采用本次默认价，需在已有配置中将 `lich_comet` / `comet_burst`
设为 200，`spore_ball` / `spore_burst` 设为 150，`gauntlet_laser` 设为 120。
Ars ’n Spells 可改变实际魔力路由和双方装备加成；本模组不强制其配置，也不依赖它。

冷却通过 Conflux 的主动施法事务检查，默认开启。按施法者、按魔符共享，换工具或编排不能绕过。
包含正在冷却魔符的编排会在主动释放前整体拒绝，并显示名称和剩余秒数；不会因此扣施法魔力。
正常魔符从主动释放时开始计时，同次重复出现只提交一次；已发出的散射、环绕、回响及持续攻击继续按原规则执行。
地潜只在实际穿墙成功后记冷却，同次同步分支完成后再提交；未成功命中／未找到出口不记冷却。
创造模式默认绕过检查和写入。自动装置、被动触发及直接 resolver 不会被当作新的主动施法。
冷却存储在施法者数据里，用服务器公共时钟计时，切换维度不会绕过。
`[cooldowns].enabled` 控制全局开关，`creativeCooldown` 控制创造模式；`[cooldowns.seconds]` 按魔符设置秒数，0 表示该魔符无冷却。

## 构建与许可

NeoForge 使用 Java 21；Forge 使用 Java 17（Gradle 可以由 Java 21 启动）。
相邻目录默认放置 Ars-Conflux 源码，也可用 `-PconfluxCheckout=...`。
将依赖放入本地 `libs/`，对应文件哈希见 `dependencies.lock.json`。
`./gradlew :jar :sourcesJar` 生成二进制和对应源码发行包。
`./gradlew :runGameTestServer` 运行本批服务端测试。

Forge 构建在 `forge/` 中运行同样命令；本地依赖见 `forge/dependencies.lock.json`。
`forge/build/libs/bomd-nouveau-0.1.0-dev.9-mc1.20.1-forge.jar` 为重映射安装产物。
魔符配方生成 Ars 4 的原生 `recipes/inputItems` 格式；两版的耗蓝、默认冷却和创造模式规则相同。
运行 `python tools/verify_release.py --forge` 检查 Forge 产物与定向测试，`--artifacts-only` 可跳过读取运行测试结果。

BOMD 作为单独依赖安装；本模组不打包其 JAR、贴图、模型或声音。
构建产物附带 LGPL、GPL、来源及修改声明，发行时同时提供对应源码。
详见 [原生行为审计](docs/native-payload-audit.md) 和 [第三方声明](THIRD_PARTY_NOTICES.md)。


## Ars 伤害成长（dev.9）

两版的联动伤害都接入 Ars `SPELL_DAMAGE_BONUS` 固定属性和 `SpellDamageEvent.Pre`／`Post`。每次原生伤害先加施法者的装备／药水属性，再交给 Pre；取消事件不造成伤害，事件可改伤害或来源，只有成功 hurt 发 Post。保留原生缓慢、中毒、穿盾、爆炸、无敌帧、伤害类型及既有强化，不改变费用／冷却或攻击数量。

直接飞弹／花瓣、延迟孢子、三种地面攻击、巨拳激光与彗星爆炸都携带原始 Ars 上下文。爆炸仅在联动调用作用域内接入，普通爆炸和原生 Boss 攻击不变；环境火焰或后续药水中毒不重复读取法术伤害属性。属性在实际命中时读取，延迟与持续攻击使用当前施法者属性。

无需 Iron 或 Ars ’n Spells；安装后者时按其原有 Ars 伤害事件桥接，不手动再叠一次 Iron 法强。NeoForge 的可选验证环境用 `-PwithArsSpells=true` 从忽略的 `libs/ars-growth` 读取本地依赖，不打包它们。该环境仅关闭魔力统一以维持测试池，伤害桥接启用；人工测试实例配置未改。

NeoForge 和 Forge 的伤害规则共享设计。平台事件总线及属性 Holder 差异由既有 Forge 模板生成处理，新增代码不依赖 NeoForge 客户端类型。测试覆盖装备加成、一次事件修改／取消、延迟喷发、原生爆炸伤害源及作用域清理；孢子原生中毒可能继续扣血，因此测试核对 Post 的单次喷发伤害，不能把后续中毒算成重复加成。

## Core 伤害 API 接入（dev.10）

最低需要 Conflux 0.1.18。原生伤害的 Ars 装备加成、Pre/Post 和同步爆炸作用域交给 Core，删除本附属的重复伤害处理与 LivingEntity 爆炸钩子。原生钩子、伤害类型、基础数值、费用和冷却保持现有规则。
